# Deems Luxe Homes website

A reverse-listing property site: buyers and tenants say what they want, and a Deems agent brings them vetted options. It also sells property management, valuation and agency services. `docs/requirements.md` is the source of truth for scope and data models.

Phase 1 is the marketing site with lead capture. Phase 2 is the web app, in this same codebase.

## Stack

Next.js (App Router), TypeScript, Tailwind v4, Payload CMS inside the Next app, Postgres, Zod with React Hook Form, Playwright, Vitest. Next and Payload versions are pinned: Payload's `@payloadcms/next` peer range decides which Next versions are allowed.

## Running things

The repo lives in WSL. Run every Node command inside WSL, never on the Windows `\\wsl.localhost` path.

| Command | What it does |
| --- | --- |
| `pnpm db:start` | Starts this project's own Postgres on port 55433 (5433 is held by a Windows service) |
| `pnpm dev` | Runs the site on http://localhost:3000 |
| `pnpm shot <route>` | Saves 1440px and 375px screenshots to `screenshots/`, and reports overflow and console errors |
| `pnpm test` | Unit tests |
| `pnpm test:e2e` | End-to-end tests, on port 3100 with a reset `deems_luxe_test` database, and stand-ins for Google and the email service (`e2e/support/stub-services.mjs`) |
| `pnpm generate:types` | Regenerates `src/payload-types.ts` after changing a collection or global |
| `pnpm generate:importmap` | Regenerates the admin import map after adding an admin component |

## Layout

- `src/app/(site)/` public pages and their root layout
- `src/app/(payload)/` Payload admin and REST API, with their own root layout
- `src/app/api/auth/google/` Google sign-in routes
- `src/collections/`, `src/globals/` Payload content types
- `src/components/ui/` shared components, previewed at `/styleguide` (not available in production)
- `src/components/layout/`, `src/components/brand/` site chrome and logo
- `src/components/forms/` lead forms, which call the server actions in `post-a-request/actions.ts` and `services/actions.ts`
- `src/content/` draft page copy that moves into the CMS once the owner signs it off
- `src/lib/` logic with no UI. `schemas/request-criteria.ts` is the request shape shared with Phase 2, so change it with care
- `src/lib/leads/` saving leads, the per-sender limit, and the lead emails retried by `/api/cron/lead-emails`

## UI rules

After any UI change, run `pnpm shot <route>`, open both screenshots, list every visible difference from what was intended (layout, spacing, type size, colour, alignment), fix them, and repeat, up to 3 rounds. Then report what still differs. Check mobile first, because most visitors are on phones. Once the owner approves a page, commit it and add a `toHaveScreenshot` test.

- **Brand tokens** are in `src/app/(site)/globals.css`: purple `#3F07C3`, gold `#FFC900`, ink `#1A1530`, paper `#FAF9FC`, line `#E6E3EE`. Sora for headings, Inter for body.
- **Gold is never text on a light background.** It fails contrast. Use it as a fill with ink text, or on purple or ink backgrounds.
- **The roofline is the one signature shape.** It comes from the D in the logo. Use the `roof` utility on photos and dark bands only.
- **The visual reference** is `design/reference/dropbox-home.png` (gitignored): its structure and rhythm, not its look or copy.
- **Avoid** all-caps labels, arrows on links and buttons, and middle-dot separators.
- **Logo:** `LogoMark` is traced from the PNG and the wordmark images are generated by `scripts/brand-assets.mjs`. Both are temporary until the vector files are in `public/brand/`.

## Content rules

Every section launches with real content or doesn't launch.

- Sections with no content don't render. Featured Properties also leaves the navigation while empty.
- Unreviewed drafts show locally with `DraftRibbon`, and never in production. Each page has a `reviewed` flag, checked against `showDrafts` from `src/lib/drafts.ts`.
- Leads are only written by the server. A lead is saved before its email is sent, so an email failure never loses it.
- Never invent staff names, registration numbers, testimonials, partner logos, statistics or properties.
- Don't claim EARB or VRB registration until the owner confirms it.
- Stock photos are for general scenes only, never presented as team members or listed properties.
- Phase 1 has no public board, so copy must not say sellers respond directly. Illustrative request cards are always badged "Example".

## Auth rules

Staff sign in with Google only. There is no password login, and no public accounts until Phase 2.

- Access is limited to emails listed in `Users`, because staff use personal Google accounts. `BOOTSTRAP_ADMIN_EMAILS` creates the first admin.
- `src/lib/auth/staff-login.ts` holds the approval rules and `src/lib/auth/session-request.ts` decides when the session cookie may be used. Change them only with their tests.
- `GOOGLE_OIDC_STUB_URL` points sign-in at the test stub. It is ignored in production.
